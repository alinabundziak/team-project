## 4. Оптимізація груп і персоналу (Dev 2)

### 4.1. Заповненість груп

**Endpoint:** `GET /api/groups/occupancy`

Доступ: авторизовані користувачі з роллю `ADMIN` або `MANAGER`.

Повертає кількість груп і дані про заповненість кожної групи.

Основні поля:
- `count` — кількість груп;
- `groups` — масив груп;
- `groupId`, `groupName` — ідентифікатор і назва групи;
- `ageYears` — цільовий вік групи;
- `childrenCount` — кількість дітей;
- `groupCapacity` — місткість групи;
- `room` — інформація про кімнату (`id`, `name`, `capacity`);
- `occupancyPercent` — відсоток заповненості групи (наприклад, `90` означає 90 %);
- `exceedsGroupCapacity` — чи перевищено місткість групи;
- `exceedsRoomCapacity` — чи перевищено місткість кімнати;
- `isOverCapacity` — чи перевищено хоча б одну з місткостей.

### 4.2. Оцінка місячних витрат на персонал

**Endpoint:** `GET /api/staff/salary-estimates`

Доступ: авторизовані користувачі з роллю `ADMIN` або `MANAGER`.

Оцінка розраховується за формулами завдання незалежно від того, чи призначені працівники фактично на відповідні посади в групах.

Формули:
- вихователь: `2000 × N + 500 × max(0, N − 12)`, де `N` — кількість дітей у групі;
- помічник вихователя: `20 000` на місяць для кожної групи;
- викладач занять: `40 000` на місяць за кожного працівника з посадою `TEACHER`;
- керівник: `80 000` на місяць, одна посада;
- оренда: `50 000 × G`, де `G` — кількість груп.

У відповіді для кожної групи передбачено:
- `groupId`, `groupName`, `room`, `childrenCount`;
- `educator` — дані про призначеного вихователя та розрахункову зарплату;
- `assistant` — дані про призначеного помічника та розрахункову зарплату;
- `monthlyPersonnelExpenses` — оцінка місячних витрат на персонал групи.

Загальна оцінка зарплат враховує витрати на персонал усіх груп, викладачів занять і одного керівника. Оцінка оренди та загальних витрат також повертається сервісом.

### 4.3. Рекомендації з оптимізації

**Endpoint:** `POST /api/optimization/recommendations`

Доступ: авторизовані користувачі з роллю `ADMIN` або `MANAGER`.

Тіло запиту не потрібне. Endpoint формує рекомендації на основі наявних даних.

Відповідь містить:
- `generatedAt` — час формування рекомендацій;
- `appliedAutomatically` — завжди `false`;
- `recommendationsCount` — кількість рекомендацій;
- `recommendations` — масив рекомендацій.

Рекомендації можуть стосуватися:
- переміщення дітей між групами з урахуванням місткості та віку;
- заповнення відсутніх посад працівниками;
- перерозподілу персоналу за наявності надлишку відповідної посади в іншій групі.

Залежно від типу рекомендація може містити:
- `reason` — пояснення причини;
- `expectedResult` — очікуваний результат;
- `applied: false` — рекомендація не застосована;
- `suggestedChildren`, `suggestedChildIds`, `suggestedChildrenCount` — запропоновані діти та їх кількість.

Формування рекомендацій не змінює призначення дітей або працівників автоматично. Рекомендації потрібно переглянути й підтвердити окремо.

### 4.4. Локальні перевірки

Для перевірки логіки без підключення до бази даних використовуються автоматизовані тести з моками.

Запуск усіх тестів:

```bash
node --test tests/*.test.js
```

Перевірка синтаксису файлів:

```bash
node --check src/modules/optimization/optimization.service.js
node --check src/modules/optimization/optimization.controller.js
node --check src/modules/groups/groups.service.js
node --check src/modules/employees/staff.service.js
node --check src/modules/payroll/payroll.service.js
```
